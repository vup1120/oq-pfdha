# IAEA PFDHA exercise benchmark

Reproduces the three case studies of the IAEA probabilistic fault
displacement hazard (PFDHA) exercise - **Kumamoto** (strike-slip), **Le
Teil** (reverse) and **Norcia** (normal) - and compares the oq-pfdha hazard
curves with the curves supplied by the exercise's hazard-analyst teams
(Valentini et al., IAEA exercise paper, Figs 4 and 6; the same curves appear
in IAEA TECDOC-2092 as Figs 14/18/21 and 15/19/22). See
[REFERENCE.md](REFERENCE.md) for provenance and
**[VALIDATION_REPORT.md](VALIDATION_REPORT.md)** for the consolidated
three-tier validation summary (model-level, published-curve, and full
workbook coverage including the epistemic trees and sensitivity cases).

## Quick start

```bash
# run everything, write computed/ CSVs + comparison_summary.json + summary table
PYTHONPATH=. python openquake/fdha/test/benchmark/IAEA/run_all.py           # all jobs
PYTHONPATH=. python openquake/fdha/test/benchmark/IAEA/run_all.py norcia    # filter

# overlay figures (requires run_all.py output)
PYTHONPATH=. python openquake/fdha/test/benchmark/IAEA/plot_comparison.py

# the same comparisons as assertions
pytest openquake/fdha/test/benchmark/IAEA/ -m benchmark -v
```

Outputs: `computed/<case>_<job>.csv`, `comparison_summary.json`,
`Figures/iaea_fig4_principal_comparison.png`,
`Figures/iaea_fig6_distributed_comparison.png`.

## Layout

- `reference/` - the teams' published hazard curves, transcribed verbatim
  from the exercise coordinators' MATLAB plotting scripts
  (`make_reference_csvs.py` regenerates the CSVs and documents the source).
- `kumamoto/`, `le_teil/`, `norcia/` - one job INI + FDHA logic tree per
  hazard-analyst model chain, plus the source models built from the
  author-provided input workbooks and shapefiles.
- `manifest.py` - job ↔ reference-curve mapping, documented post-factors and
  assertion tolerances (single source of truth for `run_all.py` and the
  pytest test).

## Exercise definition used here

Source parameters come from the author-provided workbooks
(`PFDHA Benchmarking Study - <case> - Input data.xlsx`) and shapefiles:

| Case | Source | Magnitude / rate | Principal site | Distributed site |
|---|---|---|---|---|
| Kumamoto | Uto segment (22 km, dip 60 NW, 14 km) | M6.5, 18.9e-5/yr | on-fault vertex, l/L≈0.23 | r = 5.2 km (HW) |
| Kumamoto (floating) | Futagawa zone (78 km, dip 64.6 NW) | M6.5, 64.2e-5/yr floated | same site | - |
| Le Teil | La Rouvière `LRF2_Extended5.8km` (5.8 km, dip 45 SE, 4 km) | M5.5, 4.6e-5/yr | on-fault, l/L≈0.46 | r = 0.6 km (FW) |
| Norcia | Mount Vettore (34 km, dip 47 SW, 11 km) | Gaussian characteristic MFD M6.4–7.0, Σ = 4.03e-4/yr | near SE end, l/L≈0.05 | r = 7.6 km (HW) |

The floating option uses a `simpleFaultSource` with `PeerMSR` and aspect
ratio 1.3 so the M6.5 rupture spans the full seismogenic width and floats
along strike only, matching the exercise convention (a width-limited scaling
relation would also float ruptures down-dip and dilute the
surface-rupturing rate by ~3x).

### Workbook epistemic trees vs the published single-scenario curves

All three author workbooks were audited for epistemic structure
(2026-07-11). Summary:

| Case | Workbook base case | In this benchmark |
|---|---|---|
| Kumamoto | 4 coexisting rupture sources (Uto; Futagawa+Uto; Uto+UHN; F+U+UHN) x independent magnitude/rate branches (w 0.2/0.6/0.2 each) at the r = 5.22 km site | `kumamoto/make_basecase.py` → `source_model_basecase.xml` + `smlt_basecase.xml`; jobs `distributed_P11_basecase` / `distributed_T13_basecase` |
| Le Teil | 36-end-branch tree: thickness x rupture length x magnitude x slip rate (see below) | `le_teil/make_basecase.py` → 12 source models + `smlt_basecase.xml`; job `principal_M11_basecase` |
| Norcia | no epistemic tree - single MVFS source with the Gaussian characteristic MFD (Mw 6.4-7.0, Σ = 4.03e-4/yr) | already fully implemented in the standard jobs |

In every case the **published Fig 4/6 curves correspond to the
single-scenario configuration**, not the base-case tree: the Kumamoto
Uto-only entries match Fig 6a at 0.4% (P11) / 0.1% head (T13), and the Le
Teil single-LRF_2 entries match Fig 4c at 5-11%. The tree entries are
therefore qualitative; they quantify what the full epistemic model adds.

**Kumamoto base case** (mean-collapsed: the rate level and, per source,
the three magnitude branches enter the mean hazard linearly, so each
source becomes a 3-bin incremental MFD with bin rates = w_mag x mean
rate - exact for the mean curve). Against the Uto-only published curves,
the four-source tree raises the head x1.8-2.1 (41% more rate at higher
magnitudes) and the 10-m tail x28-32 (the Mw 7.0-7.4 multi-segment
branches).

### Sensitivity cases (demonstration jobs, snapshot-validated)

The workbook sensitivity cases have **no published reference curves**;
they are implemented as demonstration jobs generated by
`make_sensitivity_cases.py` and validated by regression snapshots
(`reference_snapshots/`) plus physical-consistency assertions
(`sensitivity.py`, `run_sensitivity.py`, `test_sensitivity_cases.py`;
update snapshots with `run_sensitivity.py --update-snapshots`):

- **Kumamoto sens1/sens3** - Suizenji fault (Mw 5.8), distributed
  (r = 0.6 km) and principal (on-fault). The Petersen (2011) models
  hard-fail below M6 (outside calibration), so these use the Takao
  (2013) chains.
- **Kumamoto sens4** - the four base-case rupture sources at their
  middle branches, r = 10 km site (P11 chain).
- **Le Teil sens1** - the four fault-source combinations (w 0.25 each;
  LRF_2 with two rupture-length branches) as a 5-branch source logic
  tree built from the Cévennes shapefile, r = 0.6 km site (T13 chain).
- **Le Teil sens4** - LRF_2 + MRF_3 + PCF_2 summed, r = 0.6 km (T13).
- **Norcia sens2** - MVFS at the r = 2.4 km site (Y03 chain).
- **Norcia sens3** - MVFS + the NFS source (29 km, dip 50 SW, GR-like
  MFD Mw 5.5–6.8) at the site 7.6 km from MVFS / 3 km from NFS (Y03).

Norcia's standard jobs already cover its workbook Base Case (r = 7.6 km)
and Sensitivity Case 1 (on-fault site) - the two configurations with
published curves.

### Le Teil: single scenario vs the workbook's base-case tree

The Le Teil author workbook defines more than the single scenario used
above. Its **Base Case is an epistemic logic tree** over the 21-km La
Rouviere source: seismogenic thickness 2 km (w 0.4, rupture lengths
2.8/4.6 km), 4 km (w 0.4, 5.8 km) and 10 km (w 0.2, 21 km); three
magnitudes per geometry (w 0.3/0.4/0.3, from Mw 4.7 up to 6.73); three
slip rates (0.015/0.01/0.005 mm/yr, w 0.1/0.4/0.5) - 36 moment-balanced
end branches with site-covering rupture rates ("Moment balancing" sheet).
There are also four sensitivity cases (1: four fault-source combinations;
2: single LRF_2 scenario at the on-fault site; 3: dip flipped to NW;
4: three separate faults at the 0.6-km site).

The published Fig 4c/6b curves that this benchmark asserts against
correspond to the **single LRF_2 / Mw 5.5 / 4.6e-5 scenario (=
Sensitivity Case 2)** - evidenced by the K24/T13/L23 entries matching
those curves at 5–11%. The base-case tree is nonetheless included as
engine inputs: `le_teil/make_basecase.py` (reads the workbook) generates
`smlt_basecase.xml` + 12 `source_model_basecase_*.xml` (4 geometries x 3
magnitudes; the slip-rate level is collapsed into the mean rates, which
is exact for the mean hazard curve). Any chain can be run over the tree
by pointing `source_model_logic_tree_file` at `smlt_basecase.xml`;
`job_principal_M11_basecase.ini` does so for the M11 chain (see below).

## Result summary (2026-07-10)

All quantitative entries pass; max |relative error| against the published
team curves over the asserted range:

| Entry | max rel. err | Entry | max rel. err |
|---|---|---|---|
| Kumamoto P11 | 4.3% | Le Teil K24 | 8.5% |
| Kumamoto C24 | 11.0% | Le Teil T13 (≤1 m) | 10.7% |
| Kumamoto K24 | 3.2% | Le Teil L23 (≤1 m) | 5.3% |
| Kumamoto T13 | 7.2% | Norcia Y03 | 16.8% |
| Kumamoto L23 (≤1 m) | 5.6% | Norcia K24 | 19.7% |
| Kumamoto distributed P11 | **0.4%** | Norcia L23 | 13.3% |
| Kumamoto distributed T13 | 32.5% (limit 40%, see below) | Le Teil distributed T13 (≤1 m) | 36.7% (limit 40%, see below) |
| Kumamoto floating K24/T13/L23 | 17.4 / 5.9 / 22.3% | Norcia distributed Y03 (≤1 m) | 19.1% |

Where an entry is asserted only up to 1 m displacement, the excluded tail
sits at AFOE < 1e-8–1e-12, where the paper itself notes the curves are
controlled by each team's (unprescribed) aleatory-truncation choice.

## Known, documented deviations

- **T13 P2p factor.** The Takao et al. (2013) conditional probability of
  principal rupture at the site (P2p, TECDOC-2092 §3.2.2) is not implemented
  as a library model; the published T13 curves include it. It is applied as
  a constant `post_factor` (0.4801 Kumamoto, 0.4748 Le Teil, back-calculated
  from the published first point; the paper quotes "a factor of 0.45").
- **T13 distributed curves** (Figs 6a/6b) are computed with
  `Takao2013PrimarySR` × `Takao2014SecondarySR (100 m cell)` ×
  `Takao2013SecondaryFD (AD, n_sigma = 5)`. The curve heads match the
  published ones to 0.1% (Kumamoto) / 9% (Le Teil) - strong evidence this
  is the team's chain - but the 0.1–1 m mid-range runs up to ~35% high
  (Kumamoto) and ~35% low (Le Teil). The team's aleatory integration of the
  DD/PAD distribution is not documented in TECDOC-2092, so the shape cannot
  be reconciled further; the assertions use a 40% tolerance (Le Teil
  restricted to ≤ 1 m). The library model itself is validated against the
  Takao et al. (2013) paper's own Figs. 10/11 in `benchmark/takao_2013/`
  (all curves digitized from the paper PDF reproduce with ~1% median /
  ≤5% max error), so the residual IAEA mid-range difference is the
  team's, not ours.
- **M11 (Le Teil).** Diagnosed against the Moss & Ross (2011) paper (see
  `le_teil/diagnose_M11.py` and `Figures/iaea_leteil_M11_diagnosis.png`):
  our implementation reproduces the paper's Eq. 5 P_sr to 4 decimals and
  carries Eqs. 7–9 verbatim, but the published M11 curve **cannot be the
  single-M5.5 scenario** - normalized, it is a lognormal with median ≈1.4 m
  (⇔ MD median at **M ≈ 6.6** via the paper's own Eq. 9), whereas M5.5 caps
  the median at AD = 0.37 m / MD = 0.41 m and gives P(D > 10 m) ≈ 5e-7
  against the published 1e-2 of head. Running our chain on the workbook's
  10-km-seismogenic-thickness branch (M6.23/6.48/6.73, w = 0.2, the team's
  own Eq. 5 P_sr) lands within ~1.7x of the published head and crosses the
  curve near 1 m - evidently the team's submission is dominated by the
  large-magnitude thickness alternative (consistent with Moss & Ross's own
  magnitude-integration methodology, cf. their Los Osos example), not the
  single-M5.5 case the other Fig. 4c curves represent.

  **Plateau decomposition** (`le_teil/diagnose_M11_psr.py`,
  `Figures/iaea_leteil_M11_psr_decomposition.png`): the plateau is
  `rate x P_sr` (P(D > 0.01 m) ≈ 1), and rescaling our curve to the
  paper's plateau overlays it *exactly* up to ~10 cm (ratio 1.00–1.06) -
  so the plateau gap is purely a P_sr scale, and the fatter paper tail
  beyond ~30 cm is the separate magnitude issue above. The job uses the
  **stiff** Moss et al. (2013) branch (`reference_vs30_value = 760`),
  giving P_sr(M5.5, reverse) = 9.9% and the expected plateau
  `4.6e-5 x 0.099 = 4.6e-6`, which matches the paper's *stated* "10% for
  Mw=5.5". (The soft branch, vs30 ≤ 600, gives 15.6% → plateau 7.2e-6,
  overshooting the paper's own text; it was rejected.) The paper's
  *plotted* head, however, corresponds to an effective P_sr of only 1.2%
  (0.0122 x rate) - 8x below the 10% its own text reports, and outside
  what the soil class explains (soft/stiff differ by only 1.58x). So our
  P_sr model reproduces the value the paper *reports*; the published
  curve is internally inconsistent with it (consistent with the paper's
  caveat that Le Teil is a very shallow, 4-km event where the
  surface-rupture-probability models "may be controversial"). The entry
  stays qualitative.
  Running the chain over the full workbook base-case tree
  (`job_principal_M11_basecase.ini`) improves the tail shape in the
  published curve's direction (at 3/5 m the ratio to the published curve
  goes from 0.18/0.02 to 0.37/0.14 - the large-magnitude branches supply
  the fat tail the single-M5.5 scenario cannot) but raises the head to
  ~14x published, because the exercise's small-magnitude branches carry
  the largest rates while the published curve is consistent with the
  thickness-10 (large-M) branches alone - reinforcing the diagnosis that
  the team's submission reflects only its large-magnitude integration.
  Both M11 entries stay qualitative.
- **V24 (Le Teil / Norcia).** Same plateau decomposition as M11, but with
  the opposite conclusion (`diagnose_V24_p2d.py`,
  `Figures/iaea_V24_p2d_decomposition.png`). The distributed plateau is
  `rate x P_sr x P2d` with the gate P_sr = 1, so it equals `rate x P2d`:

  | | Le Teil (r 0.6, reverse) | Norcia (r 7.6, normal) |
  |---|---|---|
  | our plateau | 4.17e-8 | 5.02e-8 |
  | paper plateau | 2.57e-9 | 2.98e-7 |
  | ratio ours/paper | **16.2x high** | **0.17x low** |
  | gate to match | x0.062 | x5.94 |

  The two gaps point in **opposite directions** (a 96x spread), so - unlike
  M11, where one P_sr scalar explained the whole gap - **no single P_sr /
  gate convention can reconcile both**. The difference is in the distance-
  and mechanism-dependent P2d *function* (`Visini2025SecondarySR`): our
  final-model P2d decays faster with distance than the paper's, too high
  near the fault and too low far from it. This is consistent with the
  paper's Fig-6 V24 curves having been computed with the earlier (2024,
  under-review) revision of the Visini et al. model. Our
  `Visini2025Secondary*` implementation follows the final published model
  (validated directly in `benchmark/visini_et_al_2025`) and reproduces the
  TECDOC-2092 versions of the V24 curves (Figs 19/22) instead.
- **Norcia Y03** sits 6–17% above the published curve (assertion at 20%).
  The head offset (~6%) corresponds to the difference between our Youngs
  Great-Basin P_sr and the team's effective value; the exercise paper
  itself attributes team-to-team spread of this size to the P_sr choice.
